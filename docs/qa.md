# Verification record

9 October 2026. Tests use synthetic, explicitly labeled content and do not access a private Instagram account.

## Version 0.2.0: stories and single-post video viewing

The account owner confirmed that messaging works, then reported that opened videos still allowed scrolling. The previous production script reproduced an unblocked wheel event on a shared-post route (`videoScrollBlocked: false`). Four route/link regression assertions failed before the policy change and passed afterwards.

The update preserves native story links/buttons on Home, hides feed branches, converts shared Reel URLs to single-post URLs, and prevents scrolling or advancing into other video posts. It covers video dialogs that leave the conversation URL unchanged. Closing a dialog restores conversation scrolling. Controls and multiple videos inside the same selected post remain available; explicit posting mode releases the restrictions.

26 unit tests, 19 baseline browser checks, and 14 story/video browser checks pass. The browser fixture additionally covers Home feed insertion, story navigation, wheel/touch/key blocking, video-ended propagation, SPA media advances, same-URL video dialogs, returning to messages, and posting bypass. Run `bun scripts/scroll-qa.ts` alongside the updated `bun scripts/browser-qa.ts`; evidence is under ignored `work/qa`.

Home story detection uses native `/stories/` links and English story-labeled buttons. Authenticated Instagram DOM variants, other UI languages, real video playback, and physical iPhone gestures have not been verified. If Instagram supplies an unrecognized story tray, Home feed content stays hidden; this is not proof that stories will render on every account. Updating requires replacing the installed script, closing old tabs, and changing an existing shortcut URL to `https://www.instagram.com/`.

## Real-browser checks

The gstack browse harness runs the production content script on local HTML under port 4174. Evidence and the repeatable checks are generated by `scripts/browser-qa.ts` into ignored `work/qa/`.

All 19 browser assertions passed on the final local build. Covered behavior: distracting links hide while messages remain; links inserted or retargeted later are filtered; SPA pushState and direct Reels URLs return to the inbox; posting state survives navigation; Back to messages restores filtering; storage failures on entering and leaving posting mode show an error without misrepresenting the current mode; login pages remain untouched; Escape closes the panel and restores focus. Controls and the installation site were inspected at 375, 768, and 1280 CSS pixels.

An additional unauthenticated check on the real Instagram login page confirmed the script leaves focus filtering off, adds no controls, and keeps the Log in control present. Instagram emitted a ServerJS nonce validation error during that session; no claim of an error-free authenticated Instagram session is made.

## Evidence corrections

The first gstack full-page screenshots were automatically resized to a height of 2000px. They were rejected as viewport-fidelity evidence. The QA script now captures full-page images through gstack's CDP command without resizing. Panel captures use native-size viewport screenshots.

A review found that a denied session-storage write while leaving posting mode could previously leave filtering off after navigation. Both mode actions now detect write failure and display an explicit error without navigating. The browser harness exercises both directions.

## Release limits

- No physical iPhone or signed-in Instagram inbox was available for validation.
- Message delivery, account challenges, story publishing, calls, notifications, and the home-screen shortcut need a device check by the account owner.
- A userscript-host/installed MV3 execution context was not exercised; the production script was executed by the real-browser harness and evaluated on the unauthenticated Instagram page.
- No Lighthouse score is claimed. Browser visual/functional checks are not a Lighthouse audit.
- 200% browser zoom and screen-reader interaction have not been measured.
- Instagram can change its DOM and routes. Report a missing Focus button or visible distraction with browser/iOS version; never include passwords or session cookies.

These are disclosed validation gaps, not evidence of full screenshot feature parity.
